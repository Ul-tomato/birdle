# BirdWordle · 中国鸟类 Wordle

一个用汉字猜中国鸟名的 Wordle 小游戏。玩法与界面 1:1 复刻自 [MetroWordle（中国地铁站名 Wordle）](https://ul-tomato.github.io/wordle2/)，只把词库从「地铁站名」换成「中国鸟类名录」。

**在线试玩：<https://ul-tomato.github.io/birdle/>**

---

## 一、玩法

1. 从词库列表里挑一个词库（「中国鸟类全名录」，或按目划分的 12 个目）。
2. 选择要猜的鸟名字数（1～7 字不等，视词库而定）。
3. 输入一个该字数的鸟名并提交，次数不限。
4. 每次提交后每个汉字的底色会给出提示：

| 颜色 | 含义 |
| --- | --- |
| 🟩 绿色 | 该汉字正确，且位置也正确 |
| 🟨 黄色 | 该汉字存在于答案中，但位置不对 |
| ⬜ 灰色 | 答案中没有这个汉字 |

猜够 5 次还没猜出来，会出现「查看提示」按钮，点一下会直接亮出某个还没猜对的位置。也可以随时「放弃游戏」看答案。

顶栏三个按钮分别是：游戏统计（localStorage 本地保存）、游戏规则、明暗主题切换。

## 二、词库与数据

### 分类依据

- **收录范围**依据 **郑光美《中国鸟类分类与分布名录（第四版）》（科学出版社，2023）**，该书共收录中国鸟类 **1505 种**。
- **具体物种清单与分类信息**取自公开的 **《中国观鸟年报-中国鸟类名录》v10.0**（中国观鸟记录中心 / <https://www.birdreport.cn>），原始数据见 <https://github.com/makenv/bird-list-en>。
- 两份名录的收录范围一致，差异主要来自分类学处理口径与近年新记录，因此本词库为 **1501 种**。若你需要严格 1505 种的清单，需要以该书正文为准。

### 关于单字鸟名「鹗」

名录中「**鹗**」（*Pandion haliaetus*，鹰形目 / 鹗科，IUCN LC，国家二级保护）是**唯一的单字鸟名**，且已**完整收录**在词库中，所以「中国鸟类全名录」是 **1501 种**，「鹰形目」是 **55 种**。

但单字局本身没有推理过程：1 个字里只有「鹗」一个可能的答案，点开就是一发必中。原版 MetroWordle 的逻辑是「默认选中最小长度」，词库里一旦有 1 字词，**打开词库就会直接落进 1 字局白送一胜**。

因此做了一处最小改动（详见第五节第 4 条）：**默认长度跳过 1 字，选中最小长度里 ≥2 的那个**。「1」字按钮仍然保留、可以手动点着玩。

## 三、文件结构

```
.
├── index.html              游戏本体（单文件，含全部 HTML/CSS/JS）
├── word_libraries.json     词库数据，游戏运行时 fetch 读取
├── README.md               本文件
└── data/
    └── china_birds.json    完整鸟类数据库（1501 种，含目/科/学名/英文名/IUCN/保护级别）
```

游戏本身只读取同目录的 `word_libraries.json`，`data/china_birds.json` 供查阅或二次开发使用，不参与游戏运行。

`word_libraries.json` 的格式与 MetroWordle 完全一致，就是一个「词库名 → 鸟名数组」的对象：

```json
{
  "中国鸟类全名录（1501种）": ["栗树鸭", "黑雁", "红胸黑雁", "..."],
  "雁形目（60种）": ["栗树鸭", "黑雁", "红胸黑雁", "..."]
}
```

## 四、部署到 GitHub Pages

1. 在 GitHub 新建一个 **Public** 仓库，仓库名填 **`birdle`**（若改名，下面的网址也要相应改）。
   建议**不要**勾选 "Add a README file"，以免与本地文件冲突。
2. **进入 `birdle` 文件夹内部**，把 `index.html`、`word_libraries.json`、`README.md` 以及 `data` 文件夹一起上传到仓库根目录
   （网页上 "Add file → Upload files"）。
   ⚠️ 不要把 `birdle` 文件夹本身拖进去，否则仓库里会多一层，网址会变成 `/birdle/birdle/` 打不开。
3. 进入仓库 **Settings → Pages**：
   - **Source** 选 `Deploy from a branch`
   - **Branch** 选 `main`，目录选 `/ (root)`，点 **Save**
4. 等 1～2 分钟，访问 **<https://ul-tomato.github.io/birdle/>**

所有资源都是相对路径，不需要任何构建步骤，也不需要配置 base path。

## 五、与原版 MetroWordle 的差异

界面、配色、动画、弹窗结构、交互与游戏逻辑均与原版逐行一致（`index.html` 由原文件精确改写而来，全文件差异 88 行）。仅有 4 处改动：

1. **localStorage 键名 `wordleStats` → `birdleStats`。**
   两个游戏都在 `ul-tomato.github.io` 这同一个源下，共用键名会导致地铁游戏和鸟类游戏的战绩互相污染。
   （主题偏好仍沿用 `theme` 键，因此两个游戏的明暗模式保持一致。）
2. **删除了 `console.log(targetWord)`。**
   原版会把答案直接打印到浏览器控制台，等于留了一个看答案的后门。
3. **文案替换**：站名→鸟名、地铁站名→中国鸟名、该车站不在词库中→该鸟名不在词库中 等。
4. **默认字数跳过单字**（因为词库含单字鸟名「鹗」）：

   ```js
   // 原版：默认选中最小长度
   if (lengths.indexOf(length) === 0) { ... }

   // 本版：最小长度中跳过 1 字，避免开局即必中的白送局
   const defaultLength = lengths.find(l => l >= 2) || lengths[0];
   if (length === defaultLength) { ... }
   ```

   除此之外 `renderLengthOptions()` 一字未改，`1` 字按钮照常可点。

另外，词库名刻意控制在较短长度内（显示宽度 ≤ 12 个汉字位）。原版的词库名都很短（如「北京」），其卡片 CSS 对超长名称没有做 `min-w-0` 处理，`truncate` 不会真正截断，长名称会溢出卡片——所以这里是从数据侧规避，没有改动样式。

## 六、验证情况

`index.html` 已用无头 Chrome 加载真实页面 + 真实词库做过端到端测试（脚本驱动真实 DOM 点击并逐格断言结果），非人工目测。全部通过：

**基础流程**

- 13 个词库全部正常加载，浏览器控制台无任何报错；
- 「中国鸟类全名录」字数选项为 1/2/3/4/5/6/7，「鹰形目」为 1/2/3/4/5；用例覆盖 11 个 7 字鸟名；
- 构造三种反馈并逐格断言：全不命中 → `absent`；含 1 个异位汉字 → `present`；命中答案 → `correct` ×N，并弹出胜利弹窗（「恭喜你!」「你用了 3 次猜出了正确答案」）；
- 7 字鸟名（如「斑头绿拟啄木鸟」）在棋盘上不溢出容器（棋盘 672px < 容器 699px）。

**单字鸟名「鹗」专项**

| 用例 | 期望 | 结果 |
| --- | --- | --- |
| 全名录含「鹗」 | 在词库中 | ✅ |
| 全名录里 1 字的词 | 只有「鹗」一个 | ✅ |
| 打开全名录的默认字数 | `2`，不是 `1`（不白送） | ✅ |
| 手动点「1」 | 进入 1 字局，输入框上限 1，棋盘 1 格 | ✅ |
| 1 字局输入「鹗」 | 绿格 + 胜利弹窗 | ✅ |
| 鹰形目（55种） | 含「鹗」，默认字数仍为 `2` | ✅ |

**分支与边界**

| 用例 | 期望 | 结果 |
| --- | --- | --- |
| 提交字数不符的名字 | 提示「请输入 2 个字的鸟名」，不落子 | ✅ |
| 提交字数正确但不在词库的名字 | 提示「该鸟名不在词库中」，不落子 | ✅ |
| 连错 5 次 | 出现「查看提示」按钮，棋盘最多保留 5 行 | ✅ |
| 点击提示 | 亮出 1 个未猜对位置的正确汉字，其余为「?」，按钮消失 | ✅ |
| 放弃游戏 | 弹出「游戏结束」并展示正确答案逐字对照 | ✅ |
| 统计持久化 | 写入 `birdleStats`，不污染原版 `wordleStats` | ✅ |
| 主题切换 | 明暗模式可正常来回切换 | ✅ |
